# Politiko Character Sheet

A game-style "character sheet" for every member of the Philippine House of Representatives. Each member gets four policy-orientation scores (−5 to +5), a confidence rating for each, an eight-spoke radar chart, their authored bills, committees, and public links.

It reads in two modes: **Gamer** (default) and **Boomer** (plain wording). Switch with the toggle in the header.

> **These scores describe policy orientation, not competence, integrity, or whether anyone is a "good" politician.** They are produced with a custom rubric, not an official CHES assessment or a validated instrument. Read [how the research was done](docs/RESEARCH.md) before drawing conclusions.

## What's in it

| Page            | What it shows                                                                             |
| --------------- | ----------------------------------------------------------------------------------------- |
| `/`             | Roster of all 254 profiles, searchable and filterable                                     |
| `/member/:slug` | One member's sheet: scores, radar, rationale, sources, bills, committees, family, socials |
| `/versus/:a~:b` | Side-by-side comparison of two members                                                    |
| `/realm`        | Browse members by region and province                                                     |
| `/rulebook`     | Plain-language guide to the scores                                                        |
| `/errata`       | Published corrections and a way to report new ones                                        |
| `/about`        | Sources and credits                                                                       |

The four scores:

| Score                   | −5                               | +5                     |
| ----------------------- | -------------------------------- | ---------------------- |
| Economic policy         | Left (redistributive, state-led) | Right (market-led)     |
| Social values           | Conservative                     | Liberal                |
| Civil liberties         | Restrictive                      | Protective             |
| Democratic institutions | Power-concentrating              | Institution-supporting |

A score is left **blank** when the evidence covers fewer than two distinct issues. Blank means "not enough evidence", never "centrist".

## How the research was done

Short version: an AI model assessed each member against a fixed written rubric, using their bills and other public records over a five-year window ending 2026-11-01. In practice the evidence is mostly **authored and co-authored bills**; voting records were generally not reviewed, so many scores are Low or Medium confidence and many are blank.

Full explanation, limits, and the exact prompt: **[docs/RESEARCH.md](docs/RESEARCH.md)**.

## Tech stack

- [TanStack Start](https://tanstack.com/start) (React 19, file-based routing in `src/routes`) on Vite
- Tailwind CSS v4 and Radix UI primitives
- Static single-page build, hosted on GitHub Pages
- Vitest for tests
- Data is generated by Python scripts into JSON checked into the repo

## Run locally

You need [Bun](https://bun.sh) (a `bun.lock` is committed; npm also works) and Python 3 (only if you regenerate data).

```sh
git clone https://github.com/jpabellon/politiko-character-sheet.git
cd politiko-character-sheet
bun install
bun run dev
```

Other scripts:

```sh
bun run build     # static site into dist/client/
bun run preview   # serve the production build locally
bun run test      # vitest
bun run lint      # eslint
bun run format    # prettier --write .
```

## Deploy (GitHub Pages)

The site is a static single-page app, so it runs on GitHub Pages with no server. A workflow in [.github/workflows/deploy.yml](.github/workflows/deploy.yml) tests, builds, and publishes on every push to `main`.

One-time setup in your repo on GitHub:

1. Go to **Settings > Pages**.
2. Under **Build and deployment > Source**, choose **GitHub Actions**.
3. Push to `main` (or run the workflow from the **Actions** tab). The site appears at `https://<your-username>.github.io/<repo-name>/`.

How it works:

- The build sets `BASE_PATH` to `/<repo-name>/` so assets and links resolve under the project URL. For a custom domain or a `<user>.github.io` repo, set `BASE_PATH=/` in the workflow.
- `dist/client/index.html` is copied to `404.html`. GitHub Pages serves it for unknown paths, so a deep link such as `/member/some-slug` loads the app, which then renders the right page. Those requests show a 404 status in the network tab; that is expected.
- No environment variables or secrets are needed.

Build and check it locally the same way:

```sh
BASE_PATH=/politiko-character-sheet/ bun run build
cp dist/client/index.html dist/client/404.html
```

Then serve `dist/client` under that path with any static server. (`bun run dev` uses `/` and needs none of this.)

After deploying, confirm `/errata-log.txt` loads. The corrections page fetches it, and visitors can open a pre-filled public GitHub issue (labelled `errata`) from the form, or keep a report in their browser and export it as a `.txt` file. There is no server inbox, by design. When you fix something, add a dated block to `public/errata-log.txt` and close the issue.

## Updating the data

Never hand-edit the generated JSON in `src/data`. Change the source CSV, then rerun the script.

| Data                                           | Source                                                                                | Script                                                    | Output                                            |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------- |
| Scores, rationales, sources, bills, committees | `scripts/data/house_political_profiles_geo_links.csv` plus scraped House member pages | `python3 scripts/build-data.py <dir-of-scraped-markdown>` | `src/data/roster.json`, `src/data/members/*.json` |
| Social links                                   | `scripts/data/house_members_socials.csv`                                              | `python3 scripts/build-socials.py`                        | `src/data/socials.json`                           |
| Family members                                 | `scripts/data/house_family.csv`                                                       | `python3 scripts/build-family.py`                         | `src/data/family.json`                            |
| Author bill counts                             | BatasWatch API                                                                        | `python3 scripts/build-juris.py`                          | `src/data/juris-authors.json`                     |

`build-data.py` expects each House member page saved as markdown from `https://www.congress.gov.ph/house-members/view/<CODE>`, one `<CODE>.md` per member, in the directory you pass in. `build-socials.py` and `build-family.py` match on `roster.json`, so run `build-data.py` first.

Published corrections go in `public/errata-log.txt` as plain-text blocks (format is in the file header).

Axis and pole definitions live in `AXES` in `src/data/members.ts`. Components read from there, so rubric changes cannot flip a meter.
